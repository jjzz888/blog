This is a brief guide to **microvlm**, a small, dependency-free
Vision-Language Model. The project is intentionally in the style of
microgpt: strip the system down until only the algorithm remains.

The one-line version:

```text
image -> patchify -> ViT encoder -> projector -> GPT decoder -> text
```

The single new idea on top of microgpt is:

> To the language model, image patches are foreign-language tokens.

The Vision Transformer describes the image in a visual embedding language. The
projector translates those vectors into the language model's embedding space.
The decoder then does ordinary causal next-token prediction over one combined
stream of text tokens and image tokens.

Everything else is efficiency, scale, and data.

## Dataset

The fuel of a VLM is not just text. It is text grounded in pixels.

For this project the data is deliberately synthetic: an 8x8 RGB image with one
4x4 quadrant painted a saturated color. For the full color+location task with
four image tokens (`shuffle_r=1`), one example looks like this:

```text
img  (label: "red top left")        input_ids  = [BOS, <image>×4, red, top, left, EOS]
  R R R R . . . .                    image_slots = [1, 2, 3, 4]
  R R R R . . . .
  R R R R . . . .                    position :  BOS  img img img img  red  top  left  EOS
  R R R R . . . .                    target   :   -    -   -   -   red  top  left  EOS   -
  . . . . . . . .                    loss_mask:   0    0   0   0   1    1    1    1     0
  . . . . . . . .
  . . . . . . . .                    (supervise only the answer tokens + EOS;
  . . . . . . . .                     never predict an <image> or the prompt)
```

This toy data is mainly illustrative. It is a controlled wiring test, not a
real benchmark. It checks that the model can use both:

- color, which lives in the RGB channels;
- location, which lives in the active patch position.

For the headline minutes-scale demo, the target is location only:

```text
top left
```

Color still varies, but the model only has to answer where the block is. That is
the right first demo because it proves the vision path is used while keeping
scalar autograd runtime reasonable.

## Tokenizer and Patchifier

Text becomes integer token ids. The image becomes a grid of flattened patches.

The draft uses a tiny closed vocabulary because the dataset is closed:

### How to implement it

```python
import math, random

COLORS = ['red', 'green', 'blue', 'yellow']
RGB = {'red': (1.0, 0.0, 0.0), 'green': (0.0, 1.0, 0.0),
       'blue': (0.0, 0.0, 1.0), 'yellow': (1.0, 1.0, 0.0)}
VROWS, HCOLS = ['top', 'bottom'], ['left', 'right']

VOCAB = ['<pad>', '<bos>', '<eos>', '<image>',
         'red', 'green', 'blue', 'yellow', 'top', 'bottom', 'left', 'right']
stoi = {w: i for i, w in enumerate(VOCAB)}
itos = {i: w for w, i in stoi.items()}
PAD, BOS, EOS, IMG = stoi['<pad>'], stoi['<bos>'], stoi['<eos>'], stoi['<image>']

def num_image_tokens(cfg):
    """#image tokens the projector emits = #<image> slots to reserve."""
    n = (cfg['H'] // cfg['P']) * (cfg['W'] // cfg['P'])     # patch count
    return n // (cfg.get('shuffle_r', 1) ** 2)             # pixel shuffle shrinks by r²

def make_image(color, vrow, hcol, cfg, noise=0.0):
    """8×8 RGB: one quadrant filled with `color`, the rest black."""
    C, H, W = cfg['C'], cfg['H'], cfg['W']
    qh, qw = H // 2, W // 2
    img = [[[0.0] * W for _ in range(H)] for _ in range(C)]
    gy = 0 if vrow == 'top' else qh
    gx = 0 if hcol == 'left' else qw
    for c in range(C):
        for y in range(gy, gy + qh):
            for x in range(gx, gx + qw):
                img[c][y][x] = RGB[color][c]
    if noise:
        for c in range(C):
            for y in range(H):
                for x in range(W):
                    img[c][y][x] = min(1.0, max(0.0, img[c][y][x] + random.uniform(-noise, noise)))
    return img

def make_example(cfg, noise=0.0, color=None, vrow=None, hcol=None):
    color = color or random.choice(COLORS)
    vrow  = vrow  or random.choice(VROWS)
    hcol  = hcol  or random.choice(HCOLS)
    img   = make_image(color, vrow, hcol, cfg, noise)
    k = num_image_tokens(cfg)
    answer = [stoi[color], stoi[vrow], stoi[hcol]]
    input_ids   = [BOS] + [IMG] * k + answer + [EOS]
    image_slots = list(range(1, 1 + k))
    targets   = [PAD] * len(input_ids)                     # next-token targets
    loss_mask = [0]   * len(input_ids)                     # 1 where supervised
    for i in range(k, len(input_ids) - 1):                 # from last <image> onward
        targets[i], loss_mask[i] = input_ids[i + 1], 1
    return dict(img=img, input_ids=input_ids, image_slots=image_slots,
                targets=targets, loss_mask=loss_mask, label=f"{color} {vrow} {hcol}")

def decode(ids):                                           # ids -> caption string
    return ' '.join(itos[i] for i in ids if i not in (PAD, BOS, EOS, IMG))
```

**The vocabulary is tiny by design.** It has 4 control tokens (`<pad>`,
`<bos>`, `<eos>`, `<image>`) plus 8 content words: the 4 colors and 4 position
words that make up the whole answer space. The control tokens are scaffolding:
`<bos>` and `<eos>` bracket the sequence, `<pad>` fills unsupervised target
slots, and `<image>` marks positions whose embeddings will be overwritten by
projected image tokens. A real VLM reuses the full subword tokenizer of its
language model because it must emit arbitrary text. This closed-vocabulary toy
keeps `tok_emb` and `lm_head` tiny and makes cross-entropy a simple 12-way
choice.

**Sample color and location independently.** Drawing color and quadrant
uniformly prevents a shortcut where one predicts the other. The model has to
read both channel information and spatial information.

**Fix the answer order.** The answer is always `color, vertical, horizontal`,
so each output slot has a stable meaning. Randomizing answer order would only
make the toy slower without testing a useful new mechanism.

**Use saturated colors.** Red, green, blue, and yellow are intentionally far
apart in RGB space. Yellow activates two channels and has a larger raw norm,
but the encoder's RMSNorm largely removes that brightness shortcut. Harder
color pairs, such as red and orange, would test color discrimination rather
than the VLM wiring.

**This is a capability probe.** The data is synthetic and can be generated on
the fly, so the point is not dataset realism. The point is to verify that the
architecture can bind a visual attribute and a visual location, then express
the result as text.

**It is a generative model on a classification-shaped task.** The answer set is
tiny, so it looks like classification operationally. But the model still emits
tokens autoregressively through the decoder. That is deliberate: real VLMs also
answer classification, VQA, and OCR prompts by generating text rather than by
adding a special task head.

The image tokenizer is `patchify`: it cuts the image into non-overlapping
`P x P` tiles and flattens each tile into a vector. Its implementation appears
in the Vision Encoder section, where it is first used by the model. In real
VLMs the text tokenizer is a subword tokenizer, and the patchifier is usually
implemented as a convolution with `kernel_size = stride = patch_size`.

## Autograd

The scalar autograd engine is the same as microgpt. The VLM adds
more computation before the text loss, but it does not add new calculus.

### How to implement it

```python
class Value:
    """Minimal scalar autograd — identical idea to micrograd/microgpt."""
    def __init__(self, data, _children=()):
        self.data = data
        self.grad = 0.0
        self._backward = lambda: None
        self._prev = set(_children)
    def __add__(self, other):
        other = other if isinstance(other, Value) else Value(other)
        out = Value(self.data + other.data, (self, other))
        def _backward():
            self.grad += out.grad
            other.grad += out.grad
        out._backward = _backward
        return out
    def __mul__(self, other):
        other = other if isinstance(other, Value) else Value(other)
        out = Value(self.data * other.data, (self, other))
        def _backward():
            self.grad += other.data * out.grad
            other.grad += self.data * out.grad
        out._backward = _backward
        return out
    def __pow__(self, other):
        assert isinstance(other, (int, float))
        out = Value(self.data ** other, (self,))
        def _backward():
            self.grad += (other * self.data ** (other - 1)) * out.grad
        out._backward = _backward
        return out
    def exp(self):
        out = Value(math.exp(self.data), (self,))
        def _backward():
            self.grad += out.data * out.grad
        out._backward = _backward
        return out
    def log(self):
        out = Value(math.log(self.data), (self,))
        def _backward():
            self.grad += (1.0 / self.data) * out.grad
        out._backward = _backward
        return out
    def relu(self):
        out = Value(self.data if self.data > 0 else 0.0, (self,))
        def _backward():
            self.grad += (out.data > 0) * out.grad
        out._backward = _backward
        return out
    def __neg__(self):        return self * -1
    def __sub__(self, o):     return self + (-o)
    def __rsub__(self, o):    return o + (-self)
    def __radd__(self, o):    return self + o
    def __rmul__(self, o):    return self * o
    def __truediv__(self, o): return self * o ** -1
    def backward(self):
        topo, visited = [], set()
        def build(v):
            if v not in visited:
                visited.add(v)
                for c in v._prev:
                    build(c)
                topo.append(v)
        build(self)
        self.grad = 1.0
        for v in reversed(topo):
            v._backward()

def linear(x, w):
    """w: out_dim rows of in_dim weights; x: in_dim vector -> out_dim vector."""
    return [sum((wij * xj for wij, xj in zip(row, x)), Value(0.0)) for row in w]

def rmsnorm(x, g):
    n = len(x)
    ms = sum((xi * xi for xi in x), Value(0.0)) * (1.0 / n)
    inv = (ms + 1e-5) ** -0.5
    return [xi * inv * gi for xi, gi in zip(x, g)]

def softmax(logits):
    m = max(l.data for l in logits)               # for numerical stability
    exps = [(l - m).exp() for l in logits]
    s = sum(exps, Value(0.0))
    return [e / s for e in exps]

def randn(*shape, scale=1.0):
    if len(shape) == 1:
        return [Value(random.gauss(0, 1) * scale) for _ in range(shape[0])]
    return [randn(*shape[1:], scale=scale) for _ in range(shape[0])]

def mlp(x, p):
    h = [v.relu() for v in linear(x, p['fc'])]   # D -> 4D, ReLU
    return linear(h, p['proj'])                  # 4D -> D
```

One `loss.backward()` reaches the language model, the projector, and the vision
encoder.

## Parameters

The parameters are still just a big collection of scalar `Value`s. The VLM adds
two new groups on top of the microgpt decoder: a vision encoder and a small
vision-to-language bridge.

| group | what it contains | role |
|---|---|---|
| vision | patch embedding, vision positional embeddings, ViT attention/MLP weights, final norm | turns image patches into visual tokens |
| bridge | projector weights, either one linear map or the two MLP matrices used here | translates visual token width into decoder embedding width |
| language | token embeddings, decoder positional embeddings, causal attention/MLP weights, final norm, LM head | predicts the next text token |

In this note the parameter trees are ordinary nested dictionaries and lists.
`init_vit` creates the vision parameters, `init_projector` creates the bridge,
and `init_lm` creates the decoder parameters. `collect_params` then walks all
three trees and hands one flat list of `Value`s to Adam.

The bridge is the smallest but most important new part. A minimal VLM could use
one matrix:

```text
vision token (D) -> projector W -> language embedding (D_lm)
```

The version here uses a two-layer MLP instead:

```text
vision token (D or D*r*r) -> fc1 -> ReLU -> fc2 -> language embedding (D_lm)
```

Production VLMs usually initialize the vision encoder and language decoder from
pretrained checkpoints, then train mostly the projector first. The knowledge of
the model is still just floats; we added a vision side and a translator between
the vision features and the text decoder.

## GPT Decoder

The language model is a normal causal decoder. A VLM does not change it. It only
changes some of the input embeddings before the decoder sees the sequence.

### How to implement it

```python
def causal_attention(tokens, p, n_head, cache=None):
    """CAUSAL (masked) self-attention: position i attends only to keys 0..i.
    Pass a KV `cache` to decode incrementally — then `tokens` is just the NEW
    token(s) and past keys/values are reused from the cache, not recomputed.
    With cache=None it processes the whole sequence (training) unchanged."""
    hd = len(tokens[0]) // n_head
    scale = 1.0 / math.sqrt(hd)
    Kc = cache['K'] if cache else []                      # keys cached from earlier tokens
    Vc = cache['V'] if cache else []                      # values cached from earlier tokens
    base = len(Kc)                                        # how many tokens are already cached
    K = Kc + [linear(t, p['Wk']) for t in tokens]        # past (reused) + new keys
    V = Vc + [linear(t, p['Wv']) for t in tokens]        # past (reused) + new values
    if cache is not None:
        cache['K'], cache['V'] = K, V                    # remember for the next step
    out = []
    for i, t in enumerate(tokens):
        qi_full = linear(t, p['Wq'])
        pos = base + i                                   # absolute position of this query
        heads = []
        for h in range(n_head):
            sl = slice(h * hd, (h + 1) * hd)
            qi = qi_full[sl]
            scores = [sum((a * b for a, b in zip(qi, K[j][sl])), Value(0.0)) * scale
                      for j in range(pos + 1)]            # attend to keys 0..pos
            attn = softmax(scores)
            ctx = [Value(0.0) for _ in range(hd)]
            for j in range(pos + 1):
                ctx = [c + attn[j] * v for c, v in zip(ctx, V[j][sl])]
            heads.extend(ctx)
        out.append(linear(heads, p['Wo']))
    return out

def decoder_block(tokens, p, n_head, cache=None):
    normed   = [rmsnorm(t, p['ln1']) for t in tokens]
    attended = causal_attention(normed, p, n_head, cache)      # cache threaded through for decoding
    tokens   = [[a + b for a, b in zip(t, at)] for t, at in zip(tokens, attended)]
    normed   = [rmsnorm(t, p['ln2']) for t in tokens]
    mlped    = [mlp(t, p) for t in normed]
    return [[a + b for a, b in zip(t, m)] for t, m in zip(tokens, mlped)]

def gpt_forward(input_ids, lparams, cfg):
    """Text-only GPT: token ids -> per-position next-token logits (no cache)."""
    stream = [[v for v in lparams['tok_emb'][tid]] for tid in input_ids]   # ids -> D_lm
    stream = [[e + pe for e, pe in zip(tok, lparams['pos_emb'][i])]
              for i, tok in enumerate(stream)]                             # + positions
    for layer in lparams['blocks']:
        stream = decoder_block(stream, layer, cfg['lm_n_head'])
    stream = [rmsnorm(t, lparams['lnf']) for t in stream]
    return [linear(t, lparams['lm_head']) for t in stream]                 # per-position logits

def gpt_generate(prompt_ids, lparams, cfg, max_new=20, eos=None):
    """Greedy generation with a KV cache: prefill the prompt once, then emit one token
    at a time — each step runs ONLY the new token through the decoder, reusing every
    earlier token's cached keys/values (O(seq) work per token instead of O(seq²))."""
    caches = [{'K': [], 'V': []} for _ in lparams['blocks']]   # one KV cache per layer

    def step(chunk_ids, start):                                # run ids at positions start, start+1, ...
        stream = [[v for v in lparams['tok_emb'][tid]] for tid in chunk_ids]
        stream = [[e + pe for e, pe in zip(tok, lparams['pos_emb'][start + i])]
                  for i, tok in enumerate(stream)]
        for layer, cache in zip(lparams['blocks'], caches):
            stream = decoder_block(stream, layer, cfg['lm_n_head'], cache)
        return linear(rmsnorm(stream[-1], lparams['lnf']), lparams['lm_head'])   # logits, last pos

    ids = list(prompt_ids)
    logits = step(ids, 0)                                      # PREFILL: whole prompt, fills the caches
    for _ in range(max_new):
        nxt = max(range(len(logits)), key=lambda j: logits[j].data)
        ids.append(nxt)
        if nxt == eos:
            break
        logits = step([nxt], len(ids) - 1)                    # DECODE: only the new token
    return ids

def init_lm(cfg):
    D_lm, vocab, max_seq, nl = cfg['D_lm'], cfg['vocab'], cfg['max_seq'], cfg['lm_n_layer']
    mlp_hidden, s = 4 * D_lm, 0.02
    params = {
        'tok_emb':  randn(vocab, D_lm, scale=s),    # token embedding table
        'pos_emb':  randn(max_seq, D_lm, scale=s),  # decoder positions
        'lnf':      [Value(1.0) for _ in range(D_lm)],
        'lm_head':  randn(vocab, D_lm, scale=s),    # hidden -> vocab logits
        'blocks':   [],
    }
    for _ in range(nl):
        params['blocks'].append({
            'ln1': [Value(1.0) for _ in range(D_lm)], 'ln2': [Value(1.0) for _ in range(D_lm)],
            'Wq': randn(D_lm, D_lm, scale=s), 'Wk': randn(D_lm, D_lm, scale=s),
            'Wv': randn(D_lm, D_lm, scale=s), 'Wo': randn(D_lm, D_lm, scale=s),
            'fc': randn(mlp_hidden, D_lm, scale=s), 'proj': randn(D_lm, mlp_hidden, scale=s),
        })
    return params
```

**The KV cache.** In training, `cache=None`: the whole sequence is known and
each key/value is computed once. In generation, text is autoregressive, so the
naive loop would rerun the decoder over the entire prefix every time it emits a
new token. A causal token's key and value never change once computed, because it
never attends to the future, so they can be cached. `gpt_generate` keeps one KV
cache per layer, prefills the prompt once, then runs only the new token through
the decoder at each step. This is a pure speed optimization: cached decoding
should produce the same logits as repeatedly running the full prefix, just
without recomputing the past.

## Vision Encoder

The **vision encoder** is the part of a VLM that turns raw pixels into a
sequence of feature vectors the language model can consume. That *role* —
pixels in, a sequence of vectors out — is the invariant; the architecture is a
choice. In current production VLMs the encoder is most often a **Vision
Transformer (ViT)**, typically a pretrained contrastive model such as CLIP-ViT
or SigLIP.

The key insight: **a ViT is just a Transformer with the causal mask removed.** A
text decoder reads tokens left-to-right and each token may only attend to
earlier ones. A ViT reads *patches* of an image and lets every patch attend to
every other patch (bidirectional), because an image has no inherent reading
order.

ViT is not the only way to fill the role:

- **CNN backbones** (ResNet — the original CLIP shipped these — or ConvNeXt)
  produce a feature map you flatten into a token sequence.
- **Encoder-free** models like Fuyu skip a dedicated encoder entirely and
  linearly project raw image patches straight into the decoder.
- **Discrete image tokenizers** (Chameleon, via a VQ-GAN-style codebook) turn
  the image into literal token IDs rather than continuous embeddings.

The rest of this note implements the ViT route, since it is the dominant choice
and reuses the Transformer machinery directly.

### What It Produces

The encoder maps an image into **N "patch tokens"**, each a `D`-dimensional
vector — the visual equivalent of word embeddings. These tokens are later
projected into the language model's embedding space and spliced into the text
stream, where the decoder treats them like any other tokens.

> Mental model: *to the language model, image patches are just foreign-language
> tokens.*

### The Pipeline

The encoder turns an image into patch tokens in a few sequential steps. First it
**patchifies**: the `C×H×W` image is cut into non-overlapping `P×P` tiles, and
each tile is flattened into a vector of length `C·P·P`. A single **patch
embedding** — a linear map `C·P·P → D` — projects every flattened patch into the
model's working dimension `D`, giving `N` vectors. Since attention is
order-blind, we add a learned **positional embedding** (one vector per patch
slot) so the model can tell a top-left patch from a bottom-right one. Those `N`
tokens then pass through `n_layer` **bidirectional Transformer blocks** (RMSNorm
→ self-attention → residual, then RMSNorm → MLP(ReLU) → residual), and a **final
RMSNorm** cleans up the output. The result is `N` patch tokens of dim `D`, which
a projector later maps into the language model's embedding space.

The shape trace is:

```text
image (C,H,W) → N patches (C·P·P each) → N tokens (dim D) → encoder → N patch tokens (dim D)
```

For an `8×8` image with patch size `P=4`: `N = (8/4)·(8/4) = 4` patches, each
flattened to `C·P·P` values, then embedded to dim `D`.

The one detail that makes it a **ViT** and not a GPT — full vs. causal
attention:

```text
   GPT decoder (causal)            ViT encoder (bidirectional)
   query \ key  0  1  2  3         query \ key  0  1  2  3
   patch 0      x                  patch 0      x  x  x  x
   patch 1      x  x               patch 1      x  x  x  x
   patch 2      x  x  x            patch 2      x  x  x  x
   patch 3      x  x  x  x         patch 3      x  x  x  x
   (can only look back)           (every patch sees every patch)
```

### How to implement it

A minimal, dependency-free version that reuses the scalar-autograd `Value`, the
`linear` / `rmsnorm` / `softmax` / `randn` helpers, and `mlp` from the GPT
section above. A ViT block is that decoder block with the causal mask removed —
`attention` below attends to *every* patch instead of only earlier ones:

```python
def patchify(img, cfg):
    """img[c][y][x] -> list of flat patch vectors, each len C*P*P."""
    C, H, W, P = cfg['C'], cfg['H'], cfg['W'], cfg['P']
    patches = []
    for gy in range(0, H, P):
        for gx in range(0, W, P):
            vec = [img[c][y][x]
                   for c in range(C)
                   for y in range(gy, gy + P)
                   for x in range(gx, gx + P)]
            patches.append(vec)
    return patches

def attention(tokens, p, n_head):
    """Full BIDIRECTIONAL self-attention — the only change vs a GPT block."""
    N, D = len(tokens), len(tokens[0])
    hd, scale = D // n_head, 1.0 / math.sqrt(D // n_head)
    Q = [linear(t, p['Wq']) for t in tokens]
    K = [linear(t, p['Wk']) for t in tokens]
    V = [linear(t, p['Wv']) for t in tokens]
    out = []
    for i in range(N):
        heads = []
        for h in range(n_head):
            sl = slice(h * hd, (h + 1) * hd)
            qi = Q[i][sl]
            scores = [sum((a*b for a, b in zip(qi, K[j][sl])), Value(0.0)) * scale
                      for j in range(N)]          # attend to EVERY patch (no mask)
            attn = softmax(scores)
            ctx = [Value(0.0) for _ in range(hd)]
            for j in range(N):
                ctx = [c + attn[j] * v for c, v in zip(ctx, V[j][sl])]
            heads.extend(ctx)
        out.append(linear(heads, p['Wo']))
    return out

def block(tokens, p, n_head):
    normed   = [rmsnorm(t, p['ln1']) for t in tokens]
    attended = attention(normed, p, n_head)
    tokens   = [[a + b for a, b in zip(t, at)] for t, at in zip(tokens, attended)]
    normed   = [rmsnorm(t, p['ln2']) for t in tokens]
    mlped    = [mlp(t, p) for t in normed]
    return [[a + b for a, b in zip(t, m)] for t, m in zip(tokens, mlped)]

def vit_forward(img, params, cfg):
    tokens = []
    for i, patch in enumerate(patchify(img, cfg)):
        emb = linear([Value(x) for x in patch], params['patch_emb'])  # patch -> D
        emb = [e + pe for e, pe in zip(emb, params['pos_emb'][i])]    # + position
        tokens.append(emb)
    for layer in params['blocks']:
        tokens = block(tokens, layer, cfg['n_head'])
    return [rmsnorm(t, params['lnf']) for t in tokens]                # patch tokens

def init_vit(cfg):
    C, H, W, P = cfg['C'], cfg['H'], cfg['W'], cfg['P']
    D, nl = cfg['D'], cfg['n_layer']
    n_patches, patch_in, mlp_hidden = (H // P) * (W // P), C * P * P, 4 * D
    s = 0.02
    params = {
        'patch_emb': randn(D, patch_in, scale=s),   # C*P*P -> D
        'pos_emb':   randn(n_patches, D, scale=s),   # one vector per patch slot
        'lnf':       [Value(1.0) for _ in range(D)],
        'blocks':    [],
    }
    for _ in range(nl):
        params['blocks'].append({
            'ln1': [Value(1.0) for _ in range(D)], 'ln2': [Value(1.0) for _ in range(D)],
            'Wq': randn(D, D, scale=s), 'Wk': randn(D, D, scale=s),
            'Wv': randn(D, D, scale=s), 'Wo': randn(D, D, scale=s),
            'fc': randn(mlp_hidden, D, scale=s), 'proj': randn(D, mlp_hidden, scale=s),
        })
    return params
```

**No `[CLS]` token.** A classifier ViT often pools a special token; a VLM keeps
all patch tokens so the decoder can attend to visual detail.

**Positional embeddings are required.** Attention is permutation-invariant. If
we do not add a learned position vector for each patch slot, the encoder cannot
tell top-left from bottom-right. A learned table is enough here; production
systems may use 2D or rotary variants.

**Bidirectional, not causal.** This is the structural difference from the text
decoder block: the ViT drops the causal mask and lets every patch attend to
every other patch.

**Multi-head attention is not one big head.** Single-head attention computes one
softmax from the full `D`-dimensional dot product. Multi-head attention slices
the vectors into `n_head` subspaces and computes a separate softmax per slice.
Because softmax is nonlinear, `softmax(sum(partials))` is not the same as
separate `softmax(partial)` distributions per head. This is why different heads
can attend to different relationships.

**Choose head dimension, not just head count.** Since `hd = D / n_head`, more
heads make each subspace smaller. Too few heads force one attention distribution
to do everything; too many heads make each head too narrow. Real models often
keep `hd` in the rough 32-128 range. At this toy scale, `D=16, n_head=4` gives
`hd=4`, which is already quite small; dataset size and model width matter more
than fine-tuning the head count.

**Patch embedding is a convolution in disguise.** Explicit `patchify` followed
by `linear(C*P*P -> D)` is mathematically the same as a convolution with
`kernel_size = stride = P`, followed by flattening the spatial grid. The
convolution form is what production code uses because it fuses patch extraction
and projection into a fast tensor kernel. The explicit loop is kept here because
it makes the algorithm obvious.

**Training from scratch vs. production.** This toy trains the ViT from scratch.
Real VLMs usually start from a pretrained CLIP/SigLIP-style encoder, often add
token compression or tiling for high-resolution images, and train with batched
tensor code rather than scalar autograd.

**Dropout.** The minimal ViT has no dropout, which is the right default for this
teaching run. Dropout is a training configuration choice, not a core part of
the architecture. Large-scale pretraining often leaves it off because data scale
is the main regularizer; small-data fine-tuning may add a small dropout or use
vision-specific regularizers such as stochastic depth, augmentation, and weight
decay.

## Projector

The encoder hands back `N` patch tokens of dim `D`. The language model,
however, has its own embedding dimension `D_lm` and knows nothing about vision.
The **projector** (also called the *modality projector* or *connector*) is the
small bridge between them: it maps each `D`-dim patch token into a `D_lm`-dim
vector that lives in the language model's embedding space, so the decoder can
treat it like any other input token.

> Mental model: *the encoder describes the image in its own language; the
> projector translates that description into words the language model already
> understands.*

### What It Does

The projector does two jobs, the second of which is optional:

- **Re-dimension.** A linear map `D → D_lm` (often a small 2-layer MLP) puts
  vision tokens into the LM's embedding space. This is the part that *must*
  exist.
- **Compress (optional).** A vision encoder can emit hundreds of patch tokens
  per image; each one occupies a slot in the decoder's context window and costs
  attention compute. **Pixel shuffle** (a.k.a. token merging / space-to-depth)
  folds each `r×r` block of neighboring patches into a single token, trading
  token *count* for token *width*: `N` tokens of dim `D` become `N/r²` tokens
  of dim `D·r²`. The projector then maps `D·r² → D_lm`. Fewer, fatter tokens —
  no information thrown away, just regrouped. Despite the name, nothing is
  randomized: "shuffle" is borrowed from the super-resolution `PixelShuffle`
  layer (which moves values channels→space to upscale); here we use its inverse
  direction (space→channels), a deterministic reshape that lays the `r×r`
  neighbors' channel vectors end to end.

### The Pipeline

After re-dimensioning, the image tokens are **spliced** into the text embedding
stream: the prompt reserves placeholder `<image>` slots, and each slot's
embedding is overwritten by one projected image token. From there the decoder
sees a single continuous sequence and does not care which embeddings came from
pixels and which from words. The splice step itself is part of assembling the
full model, so its code lives in the final section, not the projector.

```text
N patch tokens (dim D)
   → pixel shuffle (optional)   N/r² tokens (dim D·r²)
   → projector (linear/MLP)     N/r² tokens (dim D_lm)
   → splice into <image> slots  one combined embedding stream
   → language-model decoder
```

### How to implement it

Reuses the same scalar `Value`, `linear`, and `randn` helpers as the encoder
above.

```python
def pixel_shuffle(tokens, grid_w, r):
    """Merge each r×r block of neighboring patch tokens into one wider token.
    tokens: N vectors (dim D), row-major on a (grid_h × grid_w) grid.
    Returns N/r² tokens, each of dim D·r²  (token count shrinks, width grows)."""
    N, D = len(tokens), len(tokens[0])
    grid_h = N // grid_w
    out = []
    for by in range(0, grid_h, r):
        for bx in range(0, grid_w, r):
            merged = []
            for dy in range(r):
                for dx in range(r):
                    merged.extend(tokens[(by + dy) * grid_w + (bx + dx)])  # concat channels
            out.append(merged)                                             # length D·r²
    return out

def project(tokens, params):
    """Each vision token (dim D or D·r²) -> one LM embedding (dim D_lm).
    A 2-layer MLP (LLaVA-style)."""
    out = []
    for t in tokens:
        h = [v.relu() for v in linear(t, params['fc1'])]   # D·r² -> hidden
        out.append(linear(h, params['fc2']))               # hidden -> D_lm
    return out

def vision_to_language(patch_tokens, params, cfg):
    """ViT patch tokens -> tokens ready to splice into the LM stream."""
    toks = patch_tokens
    if cfg.get('shuffle_r', 1) > 1:
        toks = pixel_shuffle(toks, cfg['grid_w'], cfg['shuffle_r'])
    return project(toks, params)

def init_projector(cfg):
    r = cfg.get('shuffle_r', 1)
    in_dim = cfg['D'] * r * r          # width after pixel shuffle
    hidden, D_lm = cfg['proj_hidden'], cfg['D_lm']
    s = 0.02
    return {
        'fc1': randn(hidden, in_dim, scale=s),
        'fc2': randn(D_lm, hidden, scale=s),
    }
```

**Why pixel shuffle.** Patch count grows with the square of image resolution,
and image tokens land inside the decoder context where attention is expensive.
Pixel shuffle compresses before the decoder sees the image: with `r=2`, four
neighboring patch tokens become one wider token. No values are discarded; they
move from the sequence axis into the channel axis, and the projector learns how
to repack them. The tradeoff is coarser spatial granularity, which can hurt
fine-localization tasks such as small document text or precise grounding.

**The projector is cheap and usually trained.** In real VLM recipes the vision
encoder and language model often start frozen, while the projector is trained
from scratch to align the two embedding spaces. It is small, but it is what
makes the image representation compatible with the decoder.

**Linear vs. MLP.** A single linear projector is the minimal bridge. A two-layer
MLP adds one nonlinearity and usually aligns the modalities better at negligible
cost for this scale.

**Bidirectional in, causal out.** The ViT creates patch features with
bidirectional attention. Once projected and spliced into the stream, those
features are read by the causal decoder like normal prefix tokens. Because they
sit before the answer, later text tokens can attend back to them.

In the minutes-scale location-only demo, `shuffle_r=2` collapses four patch
tokens into one wider token. That makes the run faster and easier to fit. The
four-token version with `shuffle_r=1` is the clearer spatial attention demo, but
it is slower in scalar Python.

## Full VLM Forward

The whole VLM is just three pieces wired in series: the **ViT encoder** turns
pixels into patch tokens, the **projector** maps those into the language
model's embedding space, and the **GPT decoder** reads the spliced text+image
stream and predicts the next token. The encoder and projector are the entire
"vision" addition — everything downstream is the plain language model,
unchanged.

So there is almost nothing new to write here. The decoder, its `decoder_block`,
and `init_lm` are exactly the GPT defined earlier. The only new function is
`vlm_forward`, which differs from `gpt_forward` in just a few lines: before
running the decoder blocks, it encodes the image, projects it, and splices the
resulting image tokens into the stream.

### The Forward Pass

```text
img, input_ids, image_slots
   1. embed text ids          input_ids  -> text_embeds   (dim D_lm)
   2. encode image            img        -> patch_tokens  (dim D)
   3. project vision->language patch_tokens -> image_tokens (dim D_lm)
   4. splice                  overwrite <image> slots with image_tokens
   5. + positional embeddings (decoder positions)
   6. causal decoder blocks   x lm_n_layer
   7. final RMSNorm -> LM head -> per-position vocab logits
```

### How to implement it

Reuses the GPT decoder (`decoder_block`, `init_lm`) from the first section, the
encoder (`vit_forward`), and the projector (`vision_to_language`). Two new
functions: `splice`, which drops the projected image tokens into the text stream
at the `<image>` slots, and `vlm_forward` — the same flow as `gpt_forward`, with
steps 2-4 inserted to bring the image in:

```python
def splice(text_embeds, image_tokens, image_slots):
    """Overwrite placeholder positions in the text stream with image tokens.
    text_embeds: list of D_lm vectors (the embedded prompt)
    image_slots: indices of the <image> placeholders, in order."""
    out = list(text_embeds)
    for slot, img in zip(image_slots, image_tokens):
        out[slot] = img
    return out

def vlm_forward(img, input_ids, image_slots, vparams, pparams, lparams, cfg):
    text_embeds  = [[v for v in lparams['tok_emb'][tid]] for tid in input_ids]  # 1. ids -> D_lm
    patch_tokens = vit_forward(img, vparams, cfg)                               # 2. image -> patches
    image_tokens = vision_to_language(patch_tokens, pparams, cfg)               # 3. -> D_lm
    stream = splice(text_embeds, image_tokens, image_slots)                     # 4. fill <image> slots
    stream = [[e + pe for e, pe in zip(tok, lparams['pos_emb'][i])]
              for i, tok in enumerate(stream)]                                  # 5. + positions
    for layer in lparams['blocks']:
        stream = decoder_block(stream, layer, cfg['lm_n_head'])                 # 6. causal decoder
    stream = [rmsnorm(t, lparams['lnf']) for t in stream]
    return [linear(t, lparams['lm_head']) for t in stream]                      # 7. per-position logits
```

Compared with `gpt_forward`, only steps 2-4 are new: the text-embedding,
positional, decoder, and head steps are identical. That is the whole point — a
VLM *is* a GPT that happens to have some of its input embeddings supplied by a
vision encoder instead of a token table.

A full forward pass (image + a tiny prompt with one `<image>` slot) returns one
vocab distribution per position. If you attach a loss to those logits, a single
`loss.backward()` pushes gradient all the way back through the language model,
the projector, *and* the vision encoder — the whole VLM is one differentiable
graph:

### Example

This smoke-test config is slightly wider/deeper than the training demo so the
shape trace exercises multiple blocks. The actual minutes-scale training run
below uses `n_layer=1` and `lm_n_layer=1` for speed.

```python
cfg = dict(C=3, H=8, W=8, P=4, D=16, n_head=4, n_layer=2,        # vision
           grid_w=2, shuffle_r=2, proj_hidden=16,                # projector
           D_lm=32, lm_n_head=4, lm_n_layer=2, vocab=12, max_seq=16)  # language
vparams, pparams, lparams = init_vit(cfg), init_projector(cfg), init_lm(cfg)
img = [[[random.random() for _ in range(cfg['W'])] for _ in range(cfg['H'])]
       for _ in range(cfg['C'])]
input_ids   = [BOS, IMG, EOS]   # one <image> placeholder
image_slots = [1]               # shuffle_r=2 on a 2x2 grid -> 1 image token -> 1 slot
logits = vlm_forward(img, input_ids, image_slots, vparams, pparams, lparams, cfg)
# logits: 3 positions x 12 vocab; a loss.backward() would reach patch_emb, fc1, tok_emb, lm_head
```

**Three modules, one graph.** The encoder, projector, and decoder are separate
parameter trees, but the forward pass builds one autograd graph. A loss at the
text output can update all three modules. To freeze part of the model, simply
omit those parameters from the optimizer.

**Splicing replaces, it does not insert.** The `<image>` placeholders are real
positions in the tokenized prompt, so positional embeddings and attention masks
already have the right length. `splice` overwrites those embeddings with
projected image tokens. The number of placeholder slots must equal the number
of projected image tokens, which is why image-token compression directly
controls context usage.

**The loss is computed on text positions only.** Image-token positions are
inputs, not prediction targets. Gradients still flow into the image path
because later supervised text positions attend back to the image tokens.

**Weight tying is optional but common.** Production decoders often tie
`lm_head` to the token embedding table, saving parameters. They are kept
separate here because the explicit version is easier to inspect.

**This is the slow, illustrative version.** Python loops over scalar `Value`s
make the dataflow visible, but real VLMs batch the same math as tensor
operations over `[batch, sequence, channels]` and use KV caching at generation
time.

## Training

With a model and a data generator in hand, training is microgpt's loop with two
VLM-specific details: the loss is **masked to the answer tokens** (we never ask
the model to predict an image patch or the prompt), and the *same* backward pass
updates the encoder, projector, and decoder at once. It is one autograd graph.

### The Loss: Masked Cross-Entropy

The objective is the standard next-token cross-entropy: the **negative
log-probability of the correct token**, summed over only the positions where
`loss_mask == 1`. Reusing the `softmax` helper and the `Value.log` method from
the GPT section, it is a one-liner.

### How to implement it

```python
def cross_entropy(logits, target):
    return -softmax(logits)[target].log()                # -log P(correct token)
```

Production writes this same loss a slightly different way — the `logsumexp`
form — for efficiency and numerical robustness. That, and why, is covered in
the Optimization Notes appendix.

### The Optimizer: A Small Adam

We use **Adam**, the standard optimizer for transformers. It keeps a
per-parameter running estimate of the gradient and its magnitude and normalizes
each step by the latter, so parameters with very different gradient scales —
tiny ones deep in the vision stack, large ones at the LM head — all make
comparable progress. That makes it forgiving of the exact learning rate. We
also decay the learning rate with a cosine schedule, which removes the
late-training oscillations Adam otherwise shows at this scale.

### How to implement it

```python
class Adam:
    """Minimal Adam over a flat list of Value parameters."""
    def __init__(self, params, lr=0.02, b1=0.9, b2=0.999, eps=1e-8):
        self.params, self.lr = params, lr
        self.b1, self.b2, self.eps = b1, b2, eps
        self.m = [0.0] * len(params); self.v = [0.0] * len(params); self.t = 0
    def zero_grad(self):
        for p in self.params: p.grad = 0.0
    def step(self):
        self.t += 1
        for i, p in enumerate(self.params):
            g = p.grad
            self.m[i] = self.b1 * self.m[i] + (1 - self.b1) * g
            self.v[i] = self.b2 * self.v[i] + (1 - self.b2) * g * g
            mhat = self.m[i] / (1 - self.b1 ** self.t)
            vhat = self.v[i] / (1 - self.b2 ** self.t)
            p.data -= self.lr * mhat / (vhat ** 0.5 + self.eps)

def collect_params(*trees):
    """Gather every Value leaf from the encoder / projector / LM parameter trees."""
    out = []
    def walk(p):
        if isinstance(p, Value):  out.append(p)
        elif isinstance(p, list): [walk(x) for x in p]
        elif isinstance(p, dict): [walk(x) for x in p.values()]
    for t in trees: walk(t)
    return out
```

### The Training Loop

The loop is microgpt's, specialized to a **location-only** target: the answer is
just the two position words, so the model must read *where* the bright patch is,
independent of its color. Build the 16 examples, then for each epoch run every
example through the VLM, sum the masked cross-entropy over the answer tokens,
and take one Adam step. A single autograd graph updates all three modules at
once.

The default here uses `shuffle_r=2`, so the four quadrant patches merge into one
image token and the demo finishes in minutes. Use `shuffle_r=1` if you want the
clearer but slower four-image-token variant.

### How to implement it

```python
def make_location_example(cfg, color, vrow, hcol):
    """One example whose target is the quadrant only — no color word."""
    img = make_image(color, vrow, hcol, cfg)
    k = num_image_tokens(cfg)
    answer = [stoi[vrow], stoi[hcol]]                          # location only
    ids = [BOS] + [IMG] * k + answer + [EOS]
    targets, mask = [PAD] * len(ids), [0] * len(ids)
    for i in range(k, len(ids) - 1):                           # supervise the answer + EOS
        targets[i], mask[i] = ids[i + 1], 1
    return dict(img=img, input_ids=ids, image_slots=list(range(1, 1 + k)),
                targets=targets, loss_mask=mask, label=f"{vrow} {hcol}")

def argmax(xs):
    return max(range(len(xs)), key=lambda j: xs[j].data)

random.seed(0)
cfg = dict(C=3, H=8, W=8, P=4, D=8, n_head=2, n_layer=1,
           grid_w=2, shuffle_r=2, proj_hidden=16,
           D_lm=16, lm_n_head=2, lm_n_layer=1, vocab=12, max_seq=16)
dataset = [make_location_example(cfg, c, v, h) for c in COLORS for v in VROWS for h in HCOLS]
vp, pp, lp = init_vit(cfg), init_projector(cfg), init_lm(cfg)
opt = Adam(collect_params(vp, pp, lp))

def accuracy():                                                # teacher-forced exact match on all 16
    hit = 0
    for ex in dataset:
        lg = vlm_forward(ex['img'], ex['input_ids'], ex['image_slots'], vp, pp, lp, cfg)
        hit += all(argmax(lg[i]) == ex['targets'][i]
                   for i, keep in enumerate(ex['loss_mask']) if keep)
    return hit / len(dataset)

EPOCHS = 40
for epoch in range(1, EPOCHS + 1):
    opt.lr = 0.002 + 0.5 * (0.02 - 0.002) * (1 + math.cos(math.pi * epoch / EPOCHS))  # cosine 0.02->0.002
    random.shuffle(dataset)
    total = 0.0
    for ex in dataset:
        logits = vlm_forward(ex['img'], ex['input_ids'], ex['image_slots'], vp, pp, lp, cfg)
        loss, n = Value(0.0), 0
        for i, keep in enumerate(ex['loss_mask']):             # masked cross-entropy
            if keep:
                loss = loss + cross_entropy(logits[i], ex['targets'][i]); n += 1
        loss = loss * (1.0 / n)                                # mean over the answer tokens
        opt.zero_grad(); loss.backward(); opt.step()           # one backward -> all three modules
        total += loss.data
    if epoch % 5 == 0:
        acc = accuracy()
        print(f"epoch {epoch:3d}  loss {total/len(dataset):.4f}  acc {acc:.2f}")
        if acc == 1.0:
            break
```

The important training rule is: image and prompt positions are inputs, not
targets. The loss is masked to answer tokens and EOS.

**Mask the loss, always.** Only answer positions get targets. Supervising the
prompt or image placeholders would teach the wrong task: the model should use
those tokens as context, not learn to predict them.

**Convergence needs budget and a sane learning rate.** On tiny spatial tasks,
accuracy can plateau while the model learns one axis before the other. That
does not necessarily mean the wiring is wrong; it may just need enough steps
and a stable learning-rate schedule.

**Freeze in production.** This note trains all modules from scratch so the
mechanism is visible. Real recipes usually start from a pretrained vision
encoder and pretrained language model, train the projector first, and unfreeze
larger parts only when needed.

**This is illustrative, not scalable.** Scalar autograd is useful because every
operation can be read directly. It is not the right execution engine for larger
runs. Vectorized tensor code keeps the same objective and architecture but runs
orders of magnitude faster.

## Inference

Generation is microgpt's autoregressive loop with a visual prefix. Encode the
image once, prefill the decoder cache, then decode one new text token at a time.

### How to implement it

```python
def generate(img, vparams, pparams, lparams, cfg, max_new=8):
    """Greedy decode with a KV cache: encode the image ONCE, prefill [BOS, <image>×k],
    then emit one token at a time, reusing the decoder's cached keys/values."""
    k = num_image_tokens(cfg)
    image_tokens = vision_to_language(vit_forward(img, vparams, cfg), pparams, cfg)  # encode once
    caches = [{'K': [], 'V': []} for _ in lparams['blocks']]               # KV cache per layer

    def step(vectors, start):                            # decode `vectors` at positions start, start+1...
        s = [[e + pe for e, pe in zip(v, lparams['pos_emb'][start + i])]
             for i, v in enumerate(vectors)]
        for layer, cache in zip(lparams['blocks'], caches):
            s = decoder_block(s, layer, cfg['lm_n_head'], cache)
        return linear(rmsnorm(s[-1], lparams['lnf']), lparams['lm_head'])  # logits, last position

    bos = [v for v in lparams['tok_emb'][BOS]]
    logits = step([bos] + image_tokens, 0)               # PREFILL: BOS + image tokens (positions 0..k)
    ids = [BOS] + [IMG] * k
    for _ in range(max_new):
        nxt = max(range(len(logits)), key=lambda j: logits[j].data)
        if nxt == EOS:
            break
        ids.append(nxt)
        logits = step([[v for v in lparams['tok_emb'][nxt]]], len(ids) - 1)  # DECODE: only the new token
    return decode(ids)                                    # drop special tokens -> string
```

### Example Use

```python
for color, vrow, hcol in [('red', 'top', 'left'), ('blue', 'bottom', 'right'), ('yellow', 'top', 'right')]:
    answer = generate(make_image(color, vrow, hcol, cfg), vp, pp, lp, cfg)
    print(f"input: {color} block, {vrow} {hcol}  ->  model: {answer!r}")
```

Expected result for a trained location-only model:

```text
input: red block, top left  ->  model: 'top left'
input: blue block, bottom right  ->  model: 'bottom right'
input: yellow block, top right  ->  model: 'top right'
```

**Greedy vs. sampling.** Greedy decoding takes the `argmax` at each step, which
is the right choice for this closed-answer toy. Open-ended captioning or chat
usually samples with temperature and top-k or top-p filtering.

**Encode once, cache the rest.** The image tokens do not change during
generation, so `generate` encodes the image once, prefills the decoder on
`[BOS] + image_tokens`, and then decodes one new token at a time with a per-layer
KV cache. Re-running the full VLM forward pass after every generated token would
produce the same greedy answer, but it wastes the already-computed keys and
values.

**Stop conditions.** Decoding stops at `EOS` or at `max_new`. The toy answers
are fixed-length, so `EOS` should arrive reliably; open-ended generation still
needs the length cap as a backstop.

**A real prompt interleaves text.** This toy can treat the question as implicit,
but a real VQA prompt contains normal text plus one or more image-token spans.
The same splice operation applies: place `<image>` slots in the prompt, replace
their embeddings with projected image tokens, then generate after the prompt.

## Real Stuff

The toy model is small, but the skeleton is the same one used by real VLMs:

| microvlm | production VLM |
|---|---|
| synthetic 8x8 images | web-scale image-text, documents, charts, screenshots, video |
| tiny closed vocabulary | full subword tokenizer |
| from-scratch ViT | pretrained CLIP/SigLIP-style vision encoder |
| small MLP projector | projector, resampler, token compressor, or Q-Former-like bridge |
| tiny GPT decoder | pretrained LLM |
| single-stage toy training | projector alignment, SFT, optional preference tuning |
| scalar Python | batched tensor kernels |

The objective is still text next-token prediction. The image is extra context.

## FAQ

**Does it actually see?**

It processes pixels through a vision encoder and uses those features to generate
text. For this toy task, that means reading color and/or location from an 8x8
image. It does not mean robust open-world image understanding.

**Why does a projector work?**

The decoder consumes vectors. Once image features have the same width as text
embeddings, causal attention can read them like any other context token.

**Why are there positional embeddings?**

Attention alone is permutation-invariant. The ViT needs patch positional
embeddings to know top-left from bottom-right. The decoder also needs text
positional embeddings for sequence order.

**Why mask the image tokens out of the loss?**

The model generates text. Image tokens are inputs, not targets. Gradients still
reach the image path because answer tokens attend back to image tokens.

**Why use the location-only demo first?**

Because it completes in minutes in scalar Python and proves the multimodal path
works. The color+location task is a better capability test, but it needs more
capacity or vectorization.

## Appendix: Optimization Notes

The readable cross-entropy says `-log P(correct token)`. The numerically stable
form used in real code is `logsumexp(logits) - logits[target]`:

### How to implement it

```python
def cross_entropy(logits, target):
    m = max(l.data for l in logits)                  # shift by the max for stability
    s = sum(((l - m).exp() for l in logits), Value(0.0))
    return (s.log() + m) - logits[target]            # logsumexp(logits) - logit[target]
```

This version replaces the readable `-softmax(logits)[target].log()` definition
from the Training section when numerical robustness matters.

Let $z_i$ be the logit for token $i$, and let $t$ be the target token. First
shift the logits by their maximum:

$$m = \max_i z_i$$

The stable log-sum-exp is:

$$\mathrm{LSE}(\mathbf{z}) = m + \log\left(\sum_i \exp(z_i - m)\right)$$

The cross-entropy loss is:

$$L = -\log \mathrm{softmax}(\mathbf{z})_t$$

After the max shift, the target probability is:

$$\mathrm{softmax}(\mathbf{z})_t = \frac{\exp(z_t - m)}{\sum_i \exp(z_i - m)}$$

So:

$$L = -\log\left(\frac{\exp(z_t - m)}{\sum_i \exp(z_i - m)}\right)$$

which simplifies to:

$$L = m + \log\left(\sum_i \exp(z_i - m)\right) - z_t$$

or, equivalently:

$$L = \mathrm{LSE}(\mathbf{z}) - z_t$$

The max shift cancels algebraically, but it keeps `exp` away from overflow and
underflow. This matters in real models because logits are not guaranteed to
stay in a small, friendly range.

Frameworks implement this as `log_softmax` plus negative log-likelihood:

$$\log \mathrm{softmax}(\mathbf{x})_i = x_i - \mathrm{LSE}(\mathbf{x})$$

$$L = -\log \mathrm{softmax}(\mathbf{x})_t$$

The gradient has the familiar compact form:

$$\nabla_{\mathbf{x}} L = \mathrm{softmax}(\mathbf{x}) - \mathbf{e}_t$$

Here $\mathbf{e}_t$ is the one-hot vector for the target token.

That compact gradient lets optimized libraries treat the loss as one fused
operation instead of separately materializing a probability vector, taking a
log, and backpropagating through each scalar step. Production training also
usually computes this loss in fp32 even when the model runs in bf16, because
the extra numerical headroom is cheap and prevents avoidable instability.
